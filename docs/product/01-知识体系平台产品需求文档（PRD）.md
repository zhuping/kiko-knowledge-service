## 1. 产品概述

### 1.1 产品定位

知识体系平台是低年级数学教育辅助 App 的知识内容基础设施，不直接面向学生提供学习页面。平台负责维护原子知识点、教材目录映射、知识点关系和正式版本，并通过接口向应用层 App 提供已发布的数据。

应用层 App 根据学生的年级、学科、教材和学习进度，选择对应的知识库正式版本，获取教材目录、知识点和知识关联，用于后续的 OCR 匹配、范围判断、举一反三和错题分析。

### 1.2 产品目标

1. 建立符合原子级知识体系报告的原子知识点数据池。
2. 支持将多个原子知识点关联到具体教材单元。
3. 支持维护原子知识点之间的前置、后继、平行和交叉关系。
4. 支持知识内容的草稿编辑、发布、版本历史和回滚。
5. 保证 App 只能读取已发布的完整知识库版本。
6. 保留后续扩展三年级、其他教材版本和题库系统的能力，但不提前实现相关业务。

### 1.3 当前范围

#### 1.3.1 本期实现

- 一年级、二年级数学上下册。
- 人教版 2024 审定新版（六三制）。
- 知识库创建、编辑、下线和版本发布。
- 教材目录加载和目录与原子知识点的多选关联。
- 原子知识点列表、新增、编辑、导入和删除。
- 原子知识点之间的前置、后继、平行、交叉关系维护。
- 发布前校验、正式版本快照、版本历史、版本差异和回滚。
- 面向 App 的已发布知识库查询能力。

#### 1.3.2 本期不实现

- 三年级及以上内容的实际录入和运营页面。
- 苏教版、北师大版等其他教材版本。
- 学生端、家长端和学习记录页面。
- OCR 识别引擎、题目匹配算法和题目生成引擎。
- 题库内容管理和题目与知识点的批量绑定。
- 知识图谱画布和图形化关系编辑。
- 复杂的多级审批流。
- 每个字段或每条记录单独发布的复杂发布机制。

### 1.4 产品原则

本产品以《低年级数学教育辅助 App 原子级知识体系构建报告》为底层理论依据，遵循以下产品原则：

- 原子知识点应独立、不可再拆、边界明确、可被题目测量。
- 一个原子知识点只聚焦一个明确的概念、技能、问题模型或应用维度。
- 知识点需要锚定教材年级、学期和教学进度。
- 知识点需要支持关键词、题目结构、解题特征、场景特征和数值特征。
- 知识点之间需要维护前置、后继、平行和交叉关系。
- 知识库内容必须通过教材映射和课程边界校验后再发布。
- 正式版本不可被直接覆盖，所有变更通过新版本生效。

本期不设置独立的知识点组业务对象，采用“教材单元 → 多个原子知识点”的组织方式。不提供小节级目录映射和知识点组的独立创建、编辑、删除流程。

### 1.5 核心闭环

```text
知识运营创建原子知识点
        ↓
知识库加载教材目录并关联知识点
        ↓
知识关联菜单维护原子知识点关系
        ↓
保存草稿并执行发布校验
        ↓
生成知识库正式版本
        ↓
App 读取正式版本
        ↓
支撑 OCR 匹配、范围判断、举一反三和错题分析
```

## 2. 核心概念和数据边界

### 2.1 原子知识点

原子知识点是知识体系中可以独立匹配、独立测量和独立维护的最小知识对象，例如：

- 100 以内数的读法。
- 10 以内加法计算。
- 9 加几的进位加法。
- 20 以内剩余问题。

原子知识点不直接绑定某一个教材单元。它可以通过知识库映射到一个或多个教材目录位置。

### 2.2 教材目录

教材目录来自经过确认的教材数据，本期对外使用教材根目录和单元两级目录。目录属于具体教材和知识库，不是全局原子知识对象。

### 2.3 知识库

知识库是供 App 选择和读取的内容集合，至少包含：

- 知识库 ID。
- 知识库名称。
- 年级和学期。
- 学科。
- 教材版本。
- 教材目录。
- 目录与原子知识点的映射。
- 当前正式版本。

例如：`人教版2024数学一年级下册` 是一个知识库。

### 2.4 知识库正式版本

正式版本是知识库在某一次发布时生成的不可修改快照。正式版本包含当时的：

- 教材目录。
- 知识点映射。
- 被引用的原子知识点内容。
- 当前知识库涉及的知识关联关系。

App 读取的是 `knowledgeBaseId + releaseVersion`，而不是后台当前正在编辑的草稿。

### 2.5 知识关联

知识关联是原子知识点之间的关系网络，包括：

- `prerequisite`：前置关系。
- `successor`：后继关系。
- `parallel`：平行关系。
- `cross`：交叉关系。

知识关联独立成一级菜单维护。它不属于某一个教材单元，但发布某个知识库时，需要把当前知识库相关的关系一并纳入正式版本快照。

### 2.6 草稿、正式版本和历史记录

平台采用两层记录：

1. **变更记录**：记录每次草稿修改的对象、修改前后内容、操作人、操作时间和修改原因。
2. **正式版本快照**：每次发布生成一个完整版本，供 App 读取和回滚。

修改草稿不会立即影响 App。正式版本不能直接修改或删除。

## 3. 用户角色和权限

### 3.1 角色

#### 编辑者

- 查看知识库、知识列表和知识关联。
- 创建和编辑草稿。
- 导入知识点。
- 取消草稿变更。
- 执行发布前校验。
- 不能发布、下线或回滚正式版本。

#### 发布者

- 拥有编辑者全部权限。
- 发布知识库。
- 下线知识库。
- 创建回滚版本。

#### 管理员

- 拥有发布者全部权限。
- 管理用户和权限。
- 查看审计记录。
- 处理异常数据和数据修复。

#### 当前版本身份范围

当前版本只启用“管理员”一种身份。管理员拥有编辑者、发布者和管理员的全部权限，可以执行知识库、知识点、知识关联的查看、新增、编辑、导入、删除、关联、发布、下线、回滚和审计操作。

编辑者、发布者等角色及其权限定义作为后续角色细分的扩展设计，当前版本不实现角色区分、权限分配和多角色协作流程。

### 3.2 权限原则

- 前端隐藏按钮不等于权限控制，后端必须执行最终校验。
- 所有新增、修改、删除、关联、发布、下线和回滚操作都记录审计信息。
- 当前管理员保存的内容进入草稿，不直接进入正式数据；后续启用角色细分后，编辑者保存规则保持不变。

## 4. 信息架构和通用交互

### 4.1 全局布局

采用中后台布局：

```text
左侧菜单                         右侧主内容
┌─────────────┐                 ┌────────────────────────┐
│ 知识库       │                 │ 页面标题                 │
│ 知识列表     │                 │ 筛选区 / 操作区           │
│ 知识关联     │                 │ 表格或详情内容             │
└─────────────┘                 └────────────────────────┘
```

发布管理不新增一级菜单，作为知识库详情中的发布和版本管理能力。

### 4.2 一级菜单

| 菜单     | 职责                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 知识库   | 管理教材版本、目录和目录与知识点的映射；执行发布、下线、历史版本和回滚 |
| 知识列表 | 管理全局原子知识点对象                                                 |
| 知识关联 | 管理原子知识点之间的关系网络                                           |

### 4.3 通用状态

#### 当前正式版本与状态

不同业务对象分别定义状态。知识库使用“待发布、已发布、已下线”三种状态；知识点和知识关联只使用“待发布、已发布”两种状态。

**知识库状态**：

| 状态   | 含义                                                                                         |
| ------ | -------------------------------------------------------------------------------------------- |
| 待发布 | 当前存在尚未进入正式版本的内容；首次创建且尚未发布、或已有正式版本但产生新修改时均使用此状态 |
| 已发布 | 已存在当前正式版本，且没有待发布内容                                                         |
| 已下线 | 已停止作为当前有效内容提供给 App，但保留正式版本和历史记录                                   |

**知识点状态**：

| 状态   | 含义                                                                                           |
| ------ | ---------------------------------------------------------------------------------------------- |
| 待发布 | 当前知识点草稿版本尚未被任何知识库正式版本发布；首次创建或已发布知识点发生新修改后均使用此状态 |
| 已发布 | 当前知识点版本已被至少一个知识库正式版本发布                                                   |

知识库列表和知识库编辑页保留“当前正式版本”字段，用于区分知识库正式快照。知识列表中的“当前正式版本”用于查看该知识点最近进入正式版本的版本信息。列表不单独展示“草稿状态”和“变更类型”。

#### 页面反馈

- 加载中：展示加载状态，不展示误导性的空数据提示。
- 空数据：展示原因和新增入口。
- 保存成功：提示保存成功并保留当前页面位置。
- 校验失败：展示错误数量，支持定位到具体字段或目录。
- 发布成功：展示新版本号，并刷新正式版本信息。
- 请求失败：展示可读错误、requestId 和重试入口。

### 4.4 草稿显示规则

列表默认展示当前草稿值，但必须同时显示正式版本状态。例如：

```text
知识点名称：100以内数的读法与写法
当前正式版本：v1
状态：待发布
```

用户可以查看“正式版本值”和“当前草稿值”的差异。App 仍然读取 v1，直到知识库发布 v2。

## 5. 模块一：知识库

### 5.1 模块定位

知识库是教材目录和原子知识点映射的管理入口，也是知识内容发布的边界。知识库页面不创建新的原子知识语义，只负责将全局知识点放入具体教材版本的目录中。

### 5.2 知识库列表页

#### 5.2.1 页面元素

页面从上到下包含：

1. 页面标题“知识库”。
2. “新建知识库”按钮。
3. 筛选区。
4. 知识库列表表格。
5. 分页和总数。

#### 5.2.2 筛选条件

- 知识库名称：输入框，支持模糊搜索。
- 年级/学期：下拉选择。
- 学科：下拉选择，当前默认数学。
- 教材：下拉选择。
- 状态：待发布、已发布、已下线。

筛选条件支持重置，刷新页面后可以保留在 URL 查询参数中。

#### 5.2.3 表格字段

| 字段         | 说明                               |
| ------------ | ---------------------------------- |
| 知识库 ID    | 系统生成的稳定标识，只读           |
| 知识库名称   | 运营人员填写的展示名称             |
| 年级/学期    | 如一年级上册、二年级下册           |
| 学科         | 当前为数学                         |
| 教材         | 如人教版2024                       |
| 当前正式版本 | 如 v1、v2；从未发布时显示“暂无”    |
| 状态         | 待发布、已发布、已下线             |
| 知识点数量   | 当前知识库关联的原子知识点数量     |
| 更新时间     | 最近一次草稿或正式版本更新时间     |
| 操作         | 详情、编辑、发布、历史、下线或删除 |

#### 5.2.4 操作状态

| 当前正式版本 | 状态   | 可用操作                               |
| ------------ | ------ | -------------------------------------- |
| 暂无         | 待发布 | 编辑、删除、发布                       |
| v1           | 已发布 | 查看、编辑、历史、下线                 |
| v1           | 待发布 | 编辑、查看变更、校验、发布、历史、下线 |
| vN           | 已下线 | 查看、编辑、历史                       |

已发布知识库不能直接删除。只有当前正式版本为“暂无”、状态为“待发布”且没有被其他数据引用的空草稿，才允许删除。

#### 5.2.5 编辑操作统一规则

列表中“编辑”的实际行为由“当前正式版本”和“状态”共同决定：

| 当前正式版本 | 状态   | 点击“编辑”后的行为                     |
| ------------ | ------ | -------------------------------------- |
| 暂无         | 待发布 | 进入当前知识库草稿继续编辑             |
| v1           | 已发布 | 基于 v1 创建草稿，进入编辑页           |
| v1           | 待发布 | 进入已有草稿继续编辑                   |
| vN           | 已下线 | 基于最近正式版本创建新草稿，进入编辑页 |

统一规则如下：

- “编辑”永远不会直接修改正式版本。
- 已发布且状态为“已发布”时，第一次点击“编辑”才创建草稿副本，并将状态改为“待发布”。
- 状态为“待发布”时，点击“编辑”直接打开当前草稿。
- 已下线知识库点击“编辑”前，需要提示将基于最近正式版本创建新草稿。
- “查看”只读展示正式版本，不产生草稿。
- “查看变更”对比当前草稿和最近正式版本。

因此，列表中的“当前正式版本”表达正式快照的版本号，“状态”表达当前发布进度，操作栏只保留统一的“编辑”动作。

### 5.3 新建知识库

#### 5.3.1 入口

点击列表页“新建知识库”，打开弹窗。

#### 5.3.2 表单字段

| 字段       | 类型   | 必填 | 说明                         |
| ---------- | ------ | ---: | ---------------------------- |
| 知识库名称 | 输入框 |   是 | 可自定义展示名称             |
| 年级/学期  | 下拉框 |   是 | 当前支持一年级、二年级上下册 |
| 学科       | 下拉框 |   是 | 当前为数学                   |
| 教材       | 下拉框 |   是 | 当前为人教版2024             |

知识库 ID 由系统生成，不允许运营人员手工修改。年级、学科和教材的组合不能重复创建同一有效知识库。

#### 5.3.3 创建后的行为

点击“保存”：

- 创建知识库草稿。
- 加载对应教材目录。
- 状态显示为“待发布”。
- App 不可读取。
- 自动进入知识库编辑页。

点击“取消”：

- 未保存时直接关闭。
- 已填写内容时提示“确认放弃本次填写吗”。

### 5.4 知识库编辑页

#### 5.4.1 页面头部

页面头部展示：

- 知识库名称。
- 年级/学期、学科、教材。
- 当前正式版本。
- 当前状态。
- 待发布变更数量。
- 最近修改人和修改时间。
- 保存草稿、发布校验、发布、查看历史按钮。

如果当前没有正式版本，显示“尚未发布”；如果已有正式版本，显示“当前正式版本 vN”。

#### 5.4.2 目录区域

目录区域直接展示创建知识库时所选学科、年级和教材对应的书本目录，平台不重新编排教材目录，只使用教材原有的目录层级。

目录区域至少支持：

- 按教材原目录层级展开/收起。
- 展示教材根目录和原有的单元名称，不展示小节。
- 目录搜索。
- 当前目录节点选中状态。
- 当前目录节点已关联的知识点数量。

本期不创建独立的知识点组，目录层级只保留教材根目录和单元。

#### 5.4.3 单元详情区域

选中左侧单元目录后，右侧进入“单元关联知识点”管理区域，采用表格展示当前单元已关联的原子知识点。

表格上方展示：

- 单元名称和完整目录路径。
- 当前关联的原子知识点数量。
- “关联知识点”按钮：打开多选弹窗，批量新增关联。
- “批量取消关联”按钮：取消已勾选的知识点与当前单元的关联。

表格没有数据时，展示空状态和“关联知识点”按钮。表格中的知识点内容只读，知识点名称、类型、关键词等原子知识属性需要进入“知识列表”编辑。

#### 5.4.4 关联知识点列表

表格字段：

| 字段         | 说明                               |
| ------------ | ---------------------------------- |
| 知识点 ID    | 原子知识点的稳定 ID                |
| 知识点名称   | 当前草稿名称                       |
| 类型         | 概念、技能等                       |
| 适用年级     | 原子知识点的适用年级               |
| 内容范围     | 课内主链或补充内容                 |
| 当前正式版本 | 该知识点最近发布到的知识库版本摘要 |
| 状态         | 待发布、已发布                     |
| 操作         | 取消关联                           |

表格支持多选。点击“取消关联”弹出确认框，确认后从当前草稿的单元映射中移除，不删除知识点对象。知识点详情和编辑统一通过“知识列表”处理。

#### 5.4.5 关联知识点弹窗

点击“关联知识点”打开多选弹窗。

弹窗元素：

- 知识点名称搜索框。
- 知识点 ID 搜索框。
- 类型筛选。
- 适用年级筛选。
- 内容范围筛选。
- 可选知识点表格。
- 已选择数量。
- 确认和取消按钮。

只能选择全局知识列表中已经存在的原子知识点。一次可以关联多个知识点。

点击确认后：

- 关联关系进入当前知识库草稿。
- 列表状态显示“待发布”。
- 不影响当前正式版本。
- 如果关闭页面前未保存，提示存在未保存变更。

#### 5.4.6 取消关联

点击“取消关联”后弹出确认框，展示：

- 知识点名称。
- 当前关联单元。
- 是否已经进入正式版本。
- 是否存在知识关联或其他引用。

草稿中的新关联可以直接移除。已经发布的关联只能标记为“待取消”，发布后才从新正式版本中移除。历史版本仍保留该关联。

### 5.5 知识库发布管理

发布管理属于知识库模块，不新增一级菜单。

#### 5.5.1 发布前状态

知识库头部显示：

```text
当前正式版本：v1
当前状态：待发布（包含 12 项变更）
```

变更包括：

- 新增或修改的知识点内容。
- 新增、修改或取消的教材映射。
- 当前知识库涉及的知识关联变更。

#### 5.5.2 发布校验

点击“发布校验”后，系统检查：

1. 知识库基本信息完整。
2. 教材目录结构合法。
3. 目录节点没有重复或断裂。
4. 关联知识点存在。
5. 知识点必填属性完整。
6. 知识点 ID 全局唯一且为以 1 开头的 8 位纯数字。
7. 关系的两端知识点存在。
8. 关系不能指向自身。
9. 前置关系不能形成循环。
10. 平行和交叉关系不能重复。
11. 需要发布的映射、知识点和关系能够组成完整快照。
12. 内容范围和教材年级不违反当前知识库范围。

校验结果分为：

- 通过：允许发布。
- 警告：允许发布，但必须在确认框中明确确认。
- 失败：禁止发布，并展示错误位置和修复建议。

#### 5.5.3 发布差异预览

发布前展示本次变更摘要：

- 新增知识点数量。
- 修改知识点数量。
- 待删除数量。
- 新增教材映射数量。
- 取消教材映射数量。
- 新增或修改关系数量。
- 受影响的教材单元。

点击具体数量可以查看明细。字段级差异至少支持查看名称、类型、关键词、题目特征和关系变化。

#### 5.5.4 发布确认

发布弹窗包含：

- 新版本号，系统自动生成。
- 变更数量。
- 校验结果。
- 发布说明，必填。
- 发布人。
- 确认发布按钮。

确认发布后，系统在一个完整事务中：

1. 固化当前知识库目录。
2. 固化目录与知识点映射。
3. 固化被引用知识点的当前内容。
4. 固化当前知识库涉及的知识关联。
5. 生成新的正式版本。
6. 更新知识库当前正式版本指针。
7. 清理已发布的草稿变更标记。
8. 写入发布审计记录。

其中任一步失败，整个发布不生效。

#### 5.5.5 发布后的状态

发布成功后：

- 知识库显示“已发布”。
- 当前正式版本更新为新版本。
- 已发布的知识点和映射显示“已发布到 vN”。
- 已发布的知识关联显示“已发布到 vN”。
- App 可以读取新版本。
- 旧版本进入历史版本，不被修改。

知识点或关系如果被多个知识库复用，当前正式版本字段展示各关联知识库版本摘要；状态按对象是否存在待发布内容以及是否仍有有效正式内容判断。

#### 5.5.6 下线

只有已发布知识库可以下线。

下线确认弹窗展示：

- 知识库名称。
- 当前正式版本。
- 下线影响。
- 是否已有替代知识库。
- 下线原因。

下线后：

- 知识库不再作为默认可用版本提供给 App。
- 历史版本仍然保留。
- 不允许直接删除正式内容。
- 可以复制为新草稿重新维护。

### 5.6 版本历史

知识库详情页提供“版本历史”入口。

#### 5.6.1 版本历史表格

| 字段     | 说明                     |
| -------- | ------------------------ |
| 版本号   | v1、v2 等                |
| 版本类型 | 正常发布、回滚发布       |
| 发布说明 | 发布时填写               |
| 发布人   | 操作人                   |
| 发布时间 | 正式生效时间             |
| 变更摘要 | 内容、映射、关系变更数量 |
| 版本角色 | 当前版本、历史版本       |
| 操作     | 查看、差异、创建回滚版本 |

#### 5.6.2 查看历史版本

历史版本只读展示：

- 当时的教材目录。
- 当时的知识点映射。
- 当时的知识点内容。
- 当时的知识关联。
- 发布说明和审计信息。

#### 5.6.3 回滚

回滚不是修改历史版本，而是以历史版本为内容基础创建一个新的正式版本。

流程：

```text
当前 v2
  ↓ 选择回滚到 v1
生成 v3 草稿/回滚草稿
  ↓ 发布确认
生成 v3 正式版本
```

回滚确认弹窗展示：

- 目标历史版本。
- 当前版本与目标版本的差异。
- 回滚后将覆盖的内容范围。
- 回滚原因。

## 6. 模块二：知识列表

### 6.1 模块定位

知识列表管理全局原子知识对象。该页面不负责将知识点绑定到具体教材单元，也不负责维护知识点之间的关系。

### 6.2 知识列表页

#### 6.2.1 页面元素

1. 页面标题“知识列表”。
2. “新增”按钮。
3. “导入”按钮。
4. 可选的“导出”按钮。
5. 筛选区。
6. 知识点表格。
7. 分页和总数。

#### 6.2.2 筛选条件

- 知识点名称：输入框，支持模糊搜索。
- 知识点 ID：输入框。
- 适用年级/学期：下拉选择。
- 学科：下拉选择。
- 类型：概念、技能、问题模型、策略、活动。
- 内容范围：课内主链、补充内容。
- 关联教材/知识库：下拉选择，用于查询映射结果，不改变知识点对象。
- 状态：待发布、已发布。

#### 6.2.3 表格字段

| 字段            | 说明                               |
| --------------- | ---------------------------------- |
| 知识点 ID       | 后端生成的以 1 开头的 8 位纯数字 `canonicalId`，只读 |
| 知识点名称      | 当前草稿值                         |
| 类型            | 五种对象类型之一                   |
| 适用年级/学期   | 该知识对象适用的教学范围           |
| 内容范围        | `core` 或 `supplement`             |
| OCR 关键词      | 核心关键词摘要                     |
| 题目结构摘要    | 题型和考查维度摘要                 |
| 关联教材/知识库 | 已关联的教材版本、知识库数量或名称 |
| 当前正式版本    | 已发布到的知识库版本摘要           |
| 状态            | 待发布、已发布                     |
| 操作            | 编辑、删除                         |

### 6.3 新增原子知识点

#### 6.3.1 表单字段

| 字段          | 类型       | 必填 | 对应 Excel 字段      | 说明                                    |
| ------------- | ---------- | ---: | -------------------- | --------------------------------------- |
| 知识点名称    | 输入框     |   是 | `name`               | 标准名称，不绑定某一教材表述            |
| 类型          | 下拉框     |   是 | `type`               | 概念、技能、问题模型、策略、活动        |
| 适用年级/学期 | 下拉框     |   是 | `grade_term`         | 一年级上、一下、二年级上、二下          |
| 内容范围      | 单选框     |   是 | `scope`              | 课内主链或补充内容                      |
| OCR 信号      | 可添加数组 |   是 | `ocr_signals`        | 用于 OCR 匹配的关键词、运算符和结构信号 |
| 题目结构摘要  | 多行文本   |   是 | `exercise_signature` | 练习题型结构摘要，不保存教材题目原文    |

`canonical_id` 由后端生成或由导入数据提供，不在人工新增表单中展示。ID 为以 1 开头的 8 位纯数字字符串，`pep24_path` 不在新增表单中维护，教材目录映射统一在知识库页面维护；`prerequisites` 不在新增表单中维护，前置关系统一在知识关联页面维护。

#### 6.3.2 知识点 ID

知识点 ID 由后端自动生成或由导入数据提供，经校验后成为稳定的 `canonicalId`。

- 固定为以 1 开头的 8 位纯数字字符串，接口中按字符串传输；
- 创建后不可修改。
- 不包含随教材位置变化的临时展示信息。
- 不能与已有知识点重复。

#### 6.3.3 保存行为

点击“保存”：

- 新知识点进入草稿。
- 状态显示“待发布”。
- 尚未关联知识库时，不会被 App 读取。
- 关闭弹窗后刷新列表。

点击“取消”：

- 未填写内容直接关闭。
- 已填写内容提示确认放弃。

### 6.4 编辑原子知识点

#### 6.4.1 未发布知识点

可以直接编辑草稿。保存后状态保持为“待发布”。

#### 6.4.2 已发布知识点

不直接修改正式版本。编辑动作创建或更新该知识点的草稿修订：

- 列表展示最新草稿值。
- 状态显示“待发布”。
- 可查看正式值与草稿值差异。
- App 继续读取旧正式版本。
- 相关知识库发布后，修改才进入新版本。

#### 6.4.3 可恢复操作

“撤销草稿修改”入口位于知识点编辑页底部操作栏，与“保存”“取消”并列展示，仅在以下条件同时满足时显示：

- 当前知识点已有正式版本。
- 当前状态为“待发布”。
- 当前存在已保存的草稿修改。

点击“撤销草稿修改”后弹出确认框，确认后将当前草稿恢复为最近正式版本内容，并执行以下处理：

- 清除当前知识点的待发布修改。
- 状态恢复为“已发布”。
- App 继续读取原正式版本，不产生新版本。
- 将撤销动作写入变更记录。

首次创建且尚未发布的知识点没有可恢复的正式版本，不显示该入口；如需移除，应从知识列表删除草稿。尚未保存的表单修改通过“取消”处理，不使用“撤销草稿修改”。

### 6.5 删除规则

- 从未发布、没有教材映射、没有关系引用的草稿知识点可以删除。
- 已进入正式版本，或仍被知识库、历史版本、关系或其他业务数据引用的知识点不能物理删除。
- 如需停止某个知识点在某个知识库中继续使用，应在该知识库中取消关联，并通过知识库发布使变更生效。
- 已删除知识点的 ID 不得重新分配给其他知识点。

### 6.6 导入

导入用于批量创建或更新原子知识点，不直接完成教材目录映射。

流程：

```text
上传 Excel
  ↓
预校验
  ↓
查看错误明细
  ↓
确认导入
  ↓
整批写入当前草稿
```

预校验阶段不得修改正式或草稿数据。确认导入后整批成功或整批失败，不执行部分写入。

错误明细至少包含：

- 行号。
- 字段名。
- 原始值。
- 错误原因。
- 修复建议。

至少校验：

- 表头和字段类型。
- 必填字段。
- `canonicalId` 是否为以 1 开头的 8 位纯数字且全局唯一。
- 枚举值。
- JSON 数组格式。
- 前置知识点 ID 是否存在。
- 知识点类型与字段内容是否冲突。

### 6.7 导出

导出文件必须标注：

- 知识库或正式版本。
- 导出时间。
- 导出人。
- 数据状态。

不得将不同知识库版本的内容混在一个无标识文件中。

## 7. 模块三：知识关联

### 7.1 模块定位

知识关联是独立的一级菜单，用于维护原子知识点之间的知识网络。它不在原子知识点创建表单中维护，也不放在知识库目录映射表单中维护。

知识关联的修改默认进入草稿。只有相关知识库发布后，关系才对 App 正式生效。

### 7.2 知识关联列表页

#### 7.2.1 页面元素

1. 页面标题“知识关联”。
2. “新建关联”按钮。
3. 筛选区。
4. 关系表格。
5. 分页和总数。

#### 7.2.2 筛选条件

- 知识点 ID。
- 知识点名称。
- 适用年级/学期。
- 类型。
- 教材或知识库影响范围。
- 状态：待发布、已发布。

#### 7.2.3 表格字段

| 字段         | 说明                     |
| ------------ | ------------------------ |
| 知识点 ID    | 当前关系的主知识点       |
| 知识点名称   | 当前关系的主知识点名称   |
| 年级/学期    | 主知识点适用范围         |
| 教材/知识库  | 当前知识点的教材映射摘要 |
| 所属单元     | 教材映射摘要             |
| 前置知识点   | 关联的前置节点列表       |
| 后继知识点   | 系统根据前置关系反向展示 |
| 平行知识点   | 平行节点列表             |
| 交叉知识点   | 交叉节点列表             |
| 当前正式版本 | 已发布到的知识库版本摘要 |
| 状态         | 待发布、已发布           |
| 操作         | 查看、编辑、删除         |

### 7.3 新建关联

#### 7.3.1 表单字段

| 字段       | 类型           | 必填 | 说明                   |
| ---------- | -------------- | ---: | ---------------------- |
| 知识点     | 可搜索下拉框   |   是 | 选择关系的主知识点     |
| 前置知识点 | 可搜索多选框   |   否 | 选择多个前置节点       |
| 后继知识点 | 展示或反向维护 |   否 | 默认由前置关系反向生成 |
| 平行知识点 | 可搜索多选框   |   否 | 选择多个并列节点       |
| 交叉知识点 | 可搜索多选框   |   否 | 选择多个跨主题节点     |
| 关系说明   | 多行文本       |   否 | 说明关系依据或边界     |

知识点候选范围来自全局知识列表，不限制在当前教材单元内，以支持跨单元和跨学期的前置关系。

#### 7.3.2 创建行为

点击确认后：

- 关系进入草稿。
- 新增关系状态显示“待发布”。
- 关系不会立即被 App 读取。
- 影响的知识库在发布校验时被识别。

### 7.4 关系规则

- 前置关系只保存一个方向，后继关系由系统反向计算。
- 不允许知识点与自身建立关系。
- 前置关系不能形成循环。
- 平行关系保存一条规范化记录，查询时双向展示。
- 交叉关系保存一条规范化记录，查询时双向展示。
- 同类型、同两端知识点的关系不能重复。
- 已正式发布的关系删除时，状态改为“待发布”，发布后从新版本移除，历史版本仍保留。

### 7.5 编辑和删除

编辑关系时：

- 已发布关系不能直接覆盖。
- 保存后状态显示“待发布”。
- 支持查看正式关系与当前草稿差异。
- 编辑页底部操作栏提供“撤销草稿修改”入口，与“保存”“取消”并列展示。
- 仅当关系已有正式版本、状态为“待发布”且存在已保存的草稿修改时显示该入口。
- 点击确认后，恢复到最近正式关系，状态恢复为“已发布”，App 继续读取原正式版本，并写入变更记录。
- 如果当前草稿是删除关系，撤销操作会取消删除标记，恢复原正式关系。
- 首次创建且尚未发布的关系没有可恢复的正式版本；如需移除，直接删除草稿关系。

删除关系时：

- 未发布的新增关系可以直接移除草稿。
- 已发布关系标记为删除，状态保持为“待发布”。
- 删除前展示关系两端和影响的知识库。

### 7.6 关系和知识库发布的关系

知识关联虽然独立维护，但不会绕过知识库版本直接上线。

发布某个知识库时：

- 系统识别该知识库中涉及的原子知识点。
- 收集这些知识点之间的当前关系草稿。
- 将相关关系一起固化到知识库正式版本。
- 只更新该知识库版本的发布状态。
- 其他知识库仍保持原有正式版本，直到它们再次发布。

## 8. 发布和版本模型

### 8.1 变更与版本

一次保存只更新草稿，不生成正式版本。一次发布生成一个完整正式版本。

```text
正式版本 v1
  ↓ 修改知识点或知识关联
当前草稿
  ↓ 发布
正式版本 v2
```

### 8.2 列表中的版本显示

知识列表和知识关联列表需要同时展示：

- 当前草稿值。
- 最近正式版本。
- 当前状态。
- 已发布到哪些知识库版本。

示例：

```text
当前名称：100以内数的读法与写法
最近正式名称：100以内数的读法
正式版本：一年级下册 v1
状态：待发布
```

### 8.3 发布的完整性

知识库发布是一个完整事务，至少同步发布：

- 教材目录。
- 教材目录与原子知识点的关联。
- 相关原子知识点的最新内容。
- 当前知识库涉及的知识关联。

不能出现“知识点已上线但映射未上线”或“关系已上线但知识点未上线”的半发布状态。

### 8.4 变更记录

每次修改记录：

- 变更对象类型。
- 对象 ID。
- 变更动作。
- 变更前值。
- 变更后值。
- 操作人。
- 操作时间。
- 修改原因。
- 影响的知识库。

变更记录不可由普通编辑者删除。

## 9. App 数据消费边界

### 9.1 App 可读取内容

App 只能读取知识库的正式版本，至少包括：

- 知识库 ID。
- 正式版本号。
- 教材目录。
- 目录与知识点映射。
- 原子知识点属性。
- 知识点关系。
- 内容范围和适用年级。

### 9.2 App 不可读取内容

- 草稿内容。
- 状态为“待发布”的关系。
- 已下线版本的默认数据。
- 不在目标正式版本中的知识点。

### 9.3 版本选择

App 可根据年级、学科和教材查询当前有效知识库，也可以指定 `releaseVersion` 读取历史正式版本。

所有正式查询响应必须返回正式版本号，便于 App 缓存和问题追踪。

## 11. 校验和验收标准

### 11.1 知识库

- 可以创建一年级、二年级上下册知识库。
- 选择教材后可以加载对应教材目录。
- 一个单元可以关联多个原子知识点。
- 取消关联不会误删原子知识点。
- 已发布知识库不能直接删除。
- 草稿修改不会影响 App。
- 发布后生成新的不可变正式版本。

### 11.2 知识列表

- 可以新增、编辑、导入和查询原子知识点。
- 创建原子知识点时不要求选择教材单元。
- `canonicalId` 为后端生成的以 1 开头的 8 位纯数字字符串，唯一且创建后不可修改。
- 已发布或被引用的知识点不能硬删除。
- 已发布知识点修改后显示正式值和草稿值差异。
- 导入失败时不产生部分写入。

### 11.3 知识关联

- 可以维护四类关系。
- 支持多选前置、平行和交叉知识点。
- 后继关系可以由前置关系反向展示。
- 不允许自关联、重复关系和前置循环。
- 关系修改不会绕过发布流程直接影响 App。
- 关系历史版本可以查看。

### 11.4 发布

- 发布前必须执行校验。
- 校验失败不能发布。
- 发布时知识点、教材映射和关系一起固化。
- 发布成功后 App 只读取新正式版本。
- 发布失败时所有内容保持原状态。
- 历史版本可以查看和回滚。
- 回滚会生成新版本，不修改历史版本。

## 12. 非功能要求

### 12.1 安全和权限

- 管理端使用公司统一登录或受控会话。
- 发布、下线和回滚必须由发布者或管理员执行。
- 当前版本只允许管理员访问和执行上述操作；发布者权限仅作为后续角色细分设计保留。
- 所有接口执行后端权限校验。
- 文件导入限制文件类型、文件大小和行数。

### 12.2 数据一致性

- 正式版本只追加，不原地更新。
- 发布使用事务保证原子性。
- 草稿和正式版本隔离。
- 正式版本中的 ID、映射和关系可追溯。

### 12.3 可用性

- 列表支持分页、筛选和空状态。
- 保存后保留当前筛选和目录位置。
- 页面离开前提示未保存变更。
- 异步导入展示进度和错误明细。
- 失败操作展示 requestId 和重试入口。

### 12.4 扩展性

- 年级、学科和教材使用可扩展枚举。
- 原子知识点不把教材位置写死在稳定 ID 中。
- 后续新增三年级时，复用知识点、目录映射、关系和发布机制。
- 后续新增教材版本时，新增教材目录和映射，不复制无必要的原子知识对象。
