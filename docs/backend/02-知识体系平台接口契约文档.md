## 1. 文档定位

本文档是 PRD、后端技术方案和前端技术方案之间的接口联调依据。接口路径、字段名、枚举值、错误码和任务返回结构以本文档为准。

V1 服务对象分为两类：

- 管理端：内部运营后台，读写当前编辑空间，路径为 `/api/v1/admin`。
- 开放端：后续业务端，只读正式发布快照，路径为 `/api/v1/open`。

## 2. 通用约定

### 2.1 请求和响应

- HTTPS、UTF-8、JSON。
- API 字段使用 camelCase；数据库字段不直接暴露。
- 时间使用 ISO 8601。
- 分页默认 `pageNum=1`、`pageSize=10`，最大 `pageSize=100`。
- 对外长期引用只使用 `canonicalId`，不使用教材路径、名称或 `knowledgeCode`。
- 数组保持 JSON 数组，不使用逗号拼接字符串。
- 正式查询响应必须返回 `releaseVersion`。

### 2.2 统一响应

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req_01J...",
  "data": {},
  "meta": {
    "releaseVersion": "2026.08.01.001"
  }
}
```

分页数据放在 `data` 中：

```json
{
  "list": [],
  "total": 0,
  "pageNum": 1,
  "pageSize": 10
}
```

### 2.3 鉴权

管理端使用公司 SSO/OIDC 或受控会话 Cookie。浏览器调用管理端接口时不携带开放接口 Secret，也不生成 HMAC 签名。

开放端使用：

```text
X-App-Key
X-Timestamp
X-Nonce
X-Signature
```

签名算法为后端技术方案规定的 HMAC-SHA256。Secret 只保存在服务端。

## 3. 稳定枚举

| 字段 | API 值 |
| --- | --- |
| `knowledgeType` | `concept`、`skill`、`problem_model`、`strategy`、`activity` |
| `gradeTerm` | `一年级上册`、`一年级下册`、`二年级上册`、`二年级下册` |
| `scope` | `core`、`supplement` |
| `status` | `draft`、`active`、`disabled` |
| `importance` | `core`、`important`、`general` |
| `cognitiveLevel` | `remember`、`understand`、`apply`、`analyze` |
| `relationType` | `prerequisite`、`parallel`、`cross` |
| `mappingType` | `introduction`、`exercise`、`review`、`application` |
| `alignmentType` | `equivalent`、`narrower`、`broader`、`related` |
| `jobStatus` | `queued`、`running`、`success`、`failed`、`cancelled` |
| `releaseType` | `normal`、`rollback` |

前端负责展示中文文案，接口只传递稳定 API 值。

## 4. 管理端接口

### 4.1 当前用户

```http
GET /api/v1/admin/me
```

响应：

```json
{
  "userId": 1001,
  "displayName": "知识运营人员",
  "roles": ["editor"],
  "permissions": ["knowledge:write", "release:validate"]
}
```

角色：`editor`、`publisher`、`admin`。

### 4.2 知识树和目录节点

```http
GET /api/v1/admin/catalog/tree?editionCode=pep_math_2024_63&spaceCode=default
```

返回完整五级树。1～4 级来自目录节点，5 级来自知识点挂载节点，但对前端统一为：

```json
{
  "id": "node-1001",
  "key": "node-1001",
  "title": "100以内数数",
  "level": 5,
  "nodeType": "knowledge",
  "canonicalId": "m.num.count.1_100",
  "status": "active",
  "children": []
}
```

目录节点：

```http
POST  /api/v1/admin/catalog/nodes
PATCH /api/v1/admin/catalog/nodes/{id}
POST  /api/v1/admin/catalog/nodes/{id}/move
```

目录节点只能建立相邻层级父子关系，移动只允许同父节点同层级排序。

第五级知识点挂载和排序：

```http
POST /api/v1/admin/catalog/knowledge-nodes
POST /api/v1/admin/catalog/knowledge-nodes/{id}/move
```

挂载请求：

```json
{
  "groupNodeId": 4001,
  "canonicalId": "m.num.count.1_100",
  "sortOrder": 10
}
```

第五级移动不得跨四级知识点组。

### 4.3 知识对象

```http
GET   /api/v1/admin/knowledge
POST  /api/v1/admin/knowledge
GET   /api/v1/admin/knowledge/{canonicalId}
PATCH /api/v1/admin/knowledge/{canonicalId}
POST  /api/v1/admin/knowledge/status:batch
```

列表筛选：`keyword`、`canonicalId`、`gradeTerm`、`knowledgeType`、`scope`、`status`、`pageNum`、`pageSize`。

新增请求至少包含：

```json
{
  "canonicalId": "m.num.count.1_100",
  "groupNodeId": 4001,
  "knowledgeName": "100以内数数",
  "knowledgeType": "skill",
  "gradeTerm": "一年级下册",
  "scope": "core",
  "cognitiveLevel": "understand",
  "importance": "core",
  "aliases": [],
  "coreKeywords": ["数到100"],
  "derivativeKeywords": [],
  "ocrSignals": ["数到100"],
  "exerciseSignature": "按顺序数数、接着数",
  "solutionFeature": "",
  "sceneFeature": "",
  "numericFeature": "",
  "rowVersion": 0
}
```

编辑时 `canonicalId` 不可修改。正式引用过的对象只能停用或恢复，不能硬删除。

### 4.4 关系

```http
GET  /api/v1/admin/relations/{canonicalId}
POST /api/v1/admin/relations/batch
```

响应按四组返回：`prerequisites`、`successors`、`parallel`、`cross`。

数据库只保存 `prerequisite` 的必要方向，`successors` 由后端反向计算。平行和交叉关系只保存一条规范化记录，接口两端都返回。

批量请求示例：

```json
{
  "operations": [
    {
      "operation": "add",
      "relationType": "prerequisite",
      "fromCanonicalId": "m.num.recognize.1_5",
      "toCanonicalId": "m.num.write.1_5",
      "basis": "知识目标依赖",
      "note": ""
    }
  ]
}
```

### 4.5 教材和政策映射

```http
GET  /api/v1/admin/textbook-mappings
POST /api/v1/admin/textbook-mappings/batch
GET  /api/v1/admin/policy-mappings
POST /api/v1/admin/policy-mappings/batch
```

教材映射字段：`canonicalId`、`editionCode`、`textbookPath`、`mappingType`、`alignmentType`、`editionLabel`、`editionKeywords`、`pageStart`、`pageEnd`、`evidence`。

V1 政策规则正文由初始化数据或管理员维护；普通运营人员只维护知识点与已有政策规则的映射。

### 4.6 导入、任务和文件

```http
POST /api/v1/admin/imports
GET  /api/v1/admin/jobs/{jobId}
GET  /api/v1/admin/jobs/{jobId}/errors
POST /api/v1/admin/jobs/{jobId}/retry
GET  /api/v1/admin/files/{fileId}
```

Excel 主工作表名为 `knowledge_points`，表头固定为：

```text
canonical_id,type,name,grade_term,scope,pep24_path,ocr_signals,exercise_signature,prerequisites
```

`ocr_signals` 和 `prerequisites` 是 JSON 数组字符串；单批最多 1000 行；预校验阶段不写业务表；确认提交时整批事务写入。

可附带 `prerequisites` 关系明细工作表，但后端以 `knowledge_points` 主工作表为导入主数据。

`prerequisites` 通过 `canonicalId` 解析，可引用其他年级的已存在知识对象。只有在本次导入范围、当前编辑空间和已有正式对象中都无法解析时，才判定为未解析引用并阻止提交。

任务响应：

```json
{
  "jobId": 1001,
  "jobType": "import",
  "status": "running",
  "totalCount": 1000,
  "successCount": 800,
  "failureCount": 10,
  "progressPercent": 81,
  "errorFileId": null,
  "canRetry": false,
  "errors": []
}
```

### 4.7 发布和版本

```http
GET  /api/v1/admin/release-changes
POST /api/v1/admin/release-batches
GET  /api/v1/admin/release-batches
GET  /api/v1/admin/release-batches/{id}
POST /api/v1/admin/release-batches/{id}/validate
POST /api/v1/admin/release-batches/{id}/publish
GET  /api/v1/admin/releases
GET  /api/v1/admin/releases/{version}/diff
POST /api/v1/admin/releases/{version}/rollback
```

发布批次详情至少包含：批次状态、版本号、基础版本、选中变更、`selectedHash`、校验结果、风险项、错误项和影响范围。

`validate` 返回任务 ID；`publish` 只有发布者或管理员可以调用。正式发布和回滚都生成新的不可变 `releaseVersion`。

### 4.8 导出

```http
POST /api/v1/admin/exports
GET  /api/v1/admin/files/{fileId}
```

导出任务必须绑定教材版本、编辑空间或正式 `releaseVersion`，文件下载权限由后端校验，链接短期有效。

## 5. 开放端接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/open/knowledge/tree` | 查询正式知识树 |
| POST | `/api/v1/open/knowledge/search` | 查询正式知识点候选 |
| POST | `/api/v1/open/knowledge/details:batch` | 批量查询正式知识点详情 |
| GET | `/api/v1/open/knowledge/{canonicalId}/relations` | 查询正式知识关系 |
| GET | `/api/v1/open/knowledge/filter` | 按教材和年级过滤正式知识点 |
| POST | `/api/v1/open/scope:check` | 返回课程范围和规则判断依据 |

开放端默认使用当前正式版本；指定历史版本时通过 `releaseVersion` 参数查询。范围判断接口不负责 OCR 和题目最终匹配。

## 6. 错误码

| HTTP | `code` | 说明 |
| --- | --- | --- |
| 400 | `PARAM_INVALID` | 参数格式或取值错误 |
| 401 | `AUTH_FAILED` | 未通过鉴权 |
| 403 | `FORBIDDEN` | 无权限 |
| 404 | `NOT_FOUND` | 资源不存在 |
| 409 | `CONFLICT` | 乐观锁、版本或重复数据冲突 |
| 422 | `VALIDATION_FAILED` | 业务规则校验失败 |
| 429 | `RATE_LIMITED` | 超出调用频率 |
| 500 | `INTERNAL_ERROR` | 未预期服务异常 |
| 503 | `SERVICE_UNAVAILABLE` | 服务未就绪 |

批量错误统一包含：`rowNumber` 或 `objectId`、`field`、`reason`、`suggestion`。错误响应不得返回 Secret、完整签名或敏感请求参数。
